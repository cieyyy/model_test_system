# 模型测试平台 PRD

## 1. 产品定义

一个模型测试兼管理平台，用于测试以及记录不同中转站（不同的模型、key--添加后默认隐藏，需要本平台的密码输入验证后才可查看、测试的项目、测试的结果）模型的测试，需输入中转站网站和对应的测试脚本，可以点击某个测试项目进行测试，也可以所有测试项目一起测试（需要弹出终端），测试完成后自动生成表格、html报告--（表格和html报告命名格式为：时间-中转站-模型），表格和html报告有默认样式模版（/Users/leyla/Documents/模型测试系统/docs/models），平台需支持导入导出、编辑、记录完整的测试时生成的文件，对于生成的文件可以实现点击文件即可弹出在线文档查看编辑（编辑基础功能都要有）导出。（支持显示json格式、md格式等市面上流行的各种格式）

## 2. 第一阶段目标

- 登记、导入、编辑中转站，填入要测试的模型，导入模型官方网站自动识别、导入、编辑模型支持的功能。
- 导入或创建测试项目、测试用例、Python 脚本和 curl 命令。
- 执行 OpenAI 兼容的 Python/curl 测试。
- 保存脱敏请求头、请求体、响应头、响应体、状态码、耗时和错误。
- 维护 `compatible`、`partial`、`unsupported`、`unknown` 四种兼容性状态。
- 导出 JSON、CSV、Excel 和 HTML 报告。
- 修改报告表格数据后实时刷新 HTML 预览。

## 3. 用户流程

```text

  -> 登记中转站和模型
  -> 选择测试模式和测试项目
  -> 预览请求计划
  -> 明确授权后执行
  -> 查看请求/响应证据
  -> 人工确认兼容性和个例结论
  -> 编辑报告表格
  -> 实时预览并导出 HTML/Excel
```

## 4. 第一阶段不做

- 不在服务器本地运行大模型。
- 不默认执行任意远程用户提交的 Python 或 shell。
- 不把 LLM Judge 的分数直接当作事实结论。
- 不覆盖已有脚本和历史原始结果。

## 5. 验收标准

- 一个测试运行可以追溯到 Provider、模型、模式、个例、脚本版本和执行时间。
- 请求和响应证据可单独查看和下载。
- API Key 在 UI、日志和导出报告中默认脱敏。
- 同一模型在不同中转站的结果不会互相覆盖。
- 修改报告表格后，HTML 预览无需手工刷新页面即可更新。
