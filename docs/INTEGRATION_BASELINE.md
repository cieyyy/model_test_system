## 5. 必须保留的测量差异

| 项目 | 已观察的差异 | 统一记录要求 |
| --- | --- | --- |
| TTFT | llm-benchmark 首个 content 或 reasoning_content；text-peak-tpm 仅正文 content；通用指标表要求可展示正文 | 分别保留 `first_generated_ms` 和 `first_content_ms`；展示时带 `ttft_basis`，缺失不可填 0 |
| TPOT | llm-benchmark 用首末文本片段；部分指标定义使用完整响应结束减 TTFT | 保留首/末正文、首/末思考、流结束时间、输出及 reasoning Token；记录 `tpot_basis`，不直接拼接不同算法样本 |
| Token | 本地 cl100k / o200k / 文本单元目标与供应商 Usage 不同 | 区分本地目标、编码名、实际 input/output/cached/reasoning；实际吞吐以 Usage 为准 |
| 缓存命中 | 指标规格有按请求数；新报告和验收有按 Token；预热计入规则也不同 | 保存 `cache_basis`、预热标记、覆盖率；请求占比和 Token 比率分别命名 |
| TPM | llm-benchmark 全程速率折算；text-peak-tpm 完整滚动 60 秒峰值；专项验收另有保守分母 | 保存 `window_kind`、时间边界、按发起/完成归属、是否含缓存；短测折算不能叫峰值 |
| Total Token | 驾驶舱早期文档写“输入、输出和缓存总速率” | 明确缓存输入通常属于输入子集，`total=input+output`，不重复加 cached |
| 成功 | 有效文本流完成、精确 PERF_OK、业务检索答案、非截断等要求不同 | 分开记录 HTTP 成功、协议完整、业务断言、验收结果；`length` 是否通过由用例标准决定 |
| 分母 | benchmark 以已发出并结束请求计算；峰值套件把客户端未发出样本也计入负载成功率；验收包区分跳过 | 保存 planned/sent/completed/success/failed/cancelled/skipped/client_dropped，保留原始分母定义 |
| 百分位 | benchmark 线性插值；峰值套件最近秩；验收包还保留保守判定值 | 保存算法、样本范围、样本数与失败处理；观测分位数和验收分位数分别展示 |
| 容量/媒体 | 100MB 合法空白传输与 100MB 有效媒体不同；本地 1M 不等于服务端 1M | 保存实发字节、body_mode、media_transport、官方 Token 及答案核验；原生视频和抽帧图片区分 |
| 状态 | 预览、执行完成、测量完整、指标达标、部署待核验是不同含义 | 不以退出码或单个 passed 覆盖所有状态，实测数值与目标值分列 |
