# 产品范围说明

版本：0.2
状态：产品定义补充

## 一句话定义

这是一个本地优先的模型测试兼管理平台：统一登记不同中转站、模型、密钥、测试项目、测试结果和测试文件，支持单项目或全量项目测试，保存完整请求响应证据，并自动生成可编辑的表格和 HTML 报告。

## 要解决的问题

平台需要能回答：

1. 哪个中转站的哪个模型可以完成某个测试项目？
2. chat、stream、JSON、工具调用、视觉、视频、缓存和长上下文分别是否支持？
3. 失败来自请求格式、中转站、模型、网络还是测试个例？
4. 这次测试能否通过请求头、请求体、响应和执行命令复核？
5. 结果表格修改后能否直接形成最终 HTML 报告？
6. 测试生成的脚本、日志、证据、表格和报告能否集中管理、在线打开、编辑和导出？

## 核心对象

| 对象 | 说明 |
| --- | --- |
| Provider | 中转站、官方接口或自定义 HTTP 服务 |
| Model | Provider 下的实际模型 ID |
| Mode | chat、stream、json、tools、vision、context 等模式 |
| Test Project | 一组可重复执行的测试项目 |
| Test Case | 项目中的具体问题、请求、脚本或断言 |
| Run | 一次实际执行记录 |
| Evidence | 不可覆盖的原始请求和响应证据 |
| Compatibility | 项目级、模式级或个例级兼容性结论 |
| Report | 可编辑的结果表格和 HTML 视图 |
| Credential | 加密保存、默认隐藏、重新认证后临时查看的中转站密钥 |
| Artifact | 测试生成的脚本、日志、请求响应、表格、报告和附件 |

## 工作流程

```text
导入历史资产或新建 Provider
  -> 输入网站、协议、模型和密钥
  -> 自动生成测试计划
  -> 选择单个项目或全部项目
  -> 弹出受控终端执行
  -> 保存运行文件和原始证据
  -> 自动生成“时间-中转站-模型”报告
  -> 在线查看、编辑和导出
```

## 第一阶段验收范围

- 可以登记中转站、模型和测试项目。
- 可以记录测试项目来源文件和原始脚本路径。
- 可以区分同一模型在不同中转站下的结果。
- 兼容性支持 `compatible`、`partial`、`unsupported`、`unknown`、`manual_review`。
- 每次运行可以追溯到 Provider、Model、Mode、Case、时间和脚本版本。
- 报告编辑不会覆盖原始证据。
- 密钥默认隐藏，只有重新认证后临时可见。
- 生成文件按运行归档，并可通过文件管理器打开。

## 明确不做

- 第一阶段不在服务器本地运行大模型。
- 未明确授权时不发送真实付费请求。
- 不把 HTTP 200 自动视为测试通过。
- 不把人工修改后的报告当成原始证据。
- 不默认开放任意远程用户执行 Python 或 shell。
